# emr-l0-core · 电子病历编辑器 L0 内核

一个**可验证**的电子病历编辑内核：模型层与写路径、AI 门控、留痕链、机读信息、
国密签章、OFD-H / WS/T 500 导出与导入、受控阅读与审计报告。

设计目标不是"功能多"，而是**每一条都能被机器证明**：
AI 只能出建议不能落笔、采纳 ≠ 确认责任、内容一变机读信息即陈旧、签名与加密用真算法而不是占位符。

- **零运行时依赖**：只用 Node 内置模块，没有 `node_modules`、没有构建步骤
- **Node ≥ 22.9**（直接用 `node` 执行 `.ts`；实测 Node v24.20.0）
- **74 个自测脚本 / 1008 条用例**（本机实测 991 通过、17 条红灯，口径与逐条原因见「已知红灯」），
  外加独立探针与真实 HTTP 契约验收

## 快速开始

```bash
npm test              # 全量自测：零依赖，直接跑
                      #   口径：`test` 链 70 个套件；另有 4 个 `test:*` 在链外
                      #   （audit-import / content-engine-model / client-exe / ui-browser）
                      #   全部 74 个 `test:*` 合计 1008 条用例 —— 本机实测 991 通过 / 17 红灯
                      #   ⚠ `test:external` 的 9 条需要外部样例（artifacts/external/*.xml），
                      #     仓库不带样例 → 它失败并**中断它后面的套件**；本机缺样例时改跑：
                      #     npm run test:phi-scan && npm run test:ui && npm run test:http
npm run typecheck     # tsc --noEmit 零错误
npm run demo          # 交互演示 → http://127.0.0.1:8787
npm run serve         # 契约服务端 → http://127.0.0.1:8801
```

**仓库里没有 `artifacts/`**，这是有意的：自测与 Demo 需要时会自己 `mkdir` 并把产物写进去
（`.gitignore` 整目录忽略）。第一次 clone 下来看不见这个目录属正常，跑完 `npm test` 就都有了。

验收与排查类命令：

| 命令 | 做什么 |
|---|---|
| `npm run verify:ofd` | 用 `tools/ofd-check` 的**独立探针**验收导出的 OFD-H（自己说导出了不算数）。⚠ 它读的 `artifacts/demo-signed.ofd` **不在仓库里**：先跑一次 `npm run test:export` 生成 |
| `npm run scan:phi` | 发布前隐私与密钥排查：患者信息 / 私钥 / 证书（命中一律打码；人工复核过的记在 `phi-scan.reviewed.json`，仍在报告里可见） |
| `npm run scan:external` | 批量导入真实外来样本，输出"能进 / 需人工 / 进不来"三档报告 |
| `npm run perf` | 性能基线（另有 `perf:1000p` 千页规模与线性度） |
| `npm run salt:new` / `salt:inspect` / `salt:reseal` | 加密快照的盐与重封装 |
| `npm run dictation-client` | **本机语音采集客户端**（医生工作站上跑）：麦克风采集 + 分片，段交给页面（页面再上传同源采集路由）。只绑 `127.0.0.1` + 一次性令牌；启动时会打印**带令牌的页面地址** |
| `npm run build:client-exe` | 把 `tools/voice-client/*.cs` 编译成 exe 版客户端（用系统自带 `csc.exe`，离线、无 NuGet）。**仓库不带预编译二进制**：想跑 `npm run dictation-client-exe` 得先本地编一次 |

## 已知红灯（开源时的真实状态）

"自测通过"这句话在别处是结论，在这里是**一个需要逐条核的数字**。下面 17 条红灯**一条都不删、不改断言口径**，
按"为什么红"分成三类：

| 类别 | 条数 | 为什么红 |
|---|---|---|
| `test:external` | 9 | 需要 `artifacts/external/*.xml` 的**外部真实样例**，仓库不带（也不该带）。放进 `artifacts/external/` 即变绿 |
| `test:ui-browser` | 2 | 需要真实 Chromium（不在默认链内） |
| `test:client-exe` | 1 个套件跑不起来 | 需要先 `npm run build:client-exe` 编出 exe（仓库不带二进制） |
| `test:ui` | 6 | **既有漂移**，逐条列在下面 |

`test:ui` 的 6 条（界面与服务端之间攒下来的不一致，每条都指向一处具体代码）：

| 用例 | 实际报的是什么 |
|---|---|
| A2 | `ui.js` 引用了页面里不存在的 4 个元素（`derivedRow` / `derivedHint` / `sidecarConflictRow` / `sidecarConflictHint`） |
| A4 | 界面调用了 `/api/dictation/capture/records`，服务端没有这条路由 |
| A6 | 面板正文段按常量算了高度（标题行高度应当由内容算出） |
| A9 | CSS 里出现两处限高（`max-height: 100%`、`max-height: 420px`），与"不许限高逼出滚动条"的纪律冲突 |
| B56 | 删掉最后一条规则时，自建包随之消失 —— 而判定方式也是包内容，包不该空掉 |
| B59 | 出厂种子判定方式 `C-BUILTIN-MISSING-TIME` 在目录里不带 `packId`（断言它落在自建包 `doc.rule.custom`） |

A9 那一条原本记的是 `.app-dialog-detail { max-height: 56vh }`（"40 项停用词清单不能把弹框顶出屏幕"的
有意例外，原始设计记录已移出本仓库）；现在报出来的已经换成另外两处 ——
**例外清单在增长，而没有人重新判过**是断言该放行还是实现该改。这类判断属产品侧，本轮按原样保留。

## 管理后台（`/admin`，独立登录页 `/login`）

医生端管病历，管理后台管**部署参数**：模型地址（决定病历内容发往哪台服务器）、采集地址
（决定**音频**发往哪台服务器）、签名服务、授权源信任根、落位策略。布局是**左栏 + 内容区**：
左栏放品牌与环境标识、四个分区、公众号二维码（关注「宏医AI」）、当前身份与退出；页头只留标题与一行说明。
版式上：表单宽度**跟语义走**（数字窄、地址宽、宽屏两列）、卡片顶部是**摘要 chip 行**、
危险操作独立在右侧并二次确认、长值**换行显示全不截断**。四个分区：

| 分区 | 内容 |
|---|---|
| 能力配置 | 模型 / **语音（转写与采集，单页）** / **预问诊接入** / 知识资产 / 质控 / 医院签名服务 / 受控阅读授权源 |
| 运行状态 | 签名服务与模型的探测留档（最近一次结论 + 成功/失败计数）、进程与容量 |
| 审计与安全 | 管理动作审计：**哪一格从什么改成什么**；登录成功与失败也在内 |
| 系统信息 | 版本 / 环境标识 / 数据目录 / **账号来源** / **生效配置指纹** |

```bash
npm run demo          # 打开 http://127.0.0.1:8787/admin —— 未登录会被送到独立登录页 /login
```

**登录是独立的一页**：未登录访问 `/admin` 时服务端直接 302 到 `/login`，**配置体的 DOM 一个字节都不下发**
（`hidden` 只挡得住"看得见"，字段名与签名字段映射的占位符照样躺在响应体里）。
登录页的 `?next=` 只接受站内路径 —— 否则它就成了开放重定向的跳板，而它长得就像"我们医院的登录页"。

**账号与口令存在数据库里**（`admin_users` 表，同一个 `l0.db`）：用户名 + 口令哈希（`scrypt`，
每条独立随机盐），角色是账号自己的属性。**代码里没有任何内置口令** —— 那正是这一轮要去掉的东西。

### 第一次运行：创建第一个管理员

库是空的时候，`/login` 下发的不是登录表单，而是**初始化表单**（由服务端二选一，另一个整段不下发）。
建完第一个管理员，这个入口就**永久关闭**（再调 `POST /api/admin/bootstrap` 会被明确拒绝）——
留在那儿就等于留了一个"谁先来谁当管理员"的后门。

如果这台机器的**服务端配置文件**里配了装机凭据（`bootstrap.token`），初始化时**必须同时提供它**：
否则"服务起来了但还没初始化"的那个窗口里，任何能访问本端口的人都能把自己变成管理员，
而装机脚本恰好是在这个窗口里访问它的。它现在**只是装机凭据，不再是登录口令** ——
`L0_QC_TOKEN` / `L0_CLINICIAN_TOKEN` 已彻底不再使用（角色现在来自账号，
而"再加一个质控员"在共享口令模型下根本表达不出来）。

想在部署时免手点一遍：写**服务端配置文件** `<运行目录>/server-config.json`
（首次启动会自动生成模板，运行目录见启动日志），填 `bootstrap` 两格：

```json
{
  "stateKey": "填密钥管理给出的高熵口令（留空 = 用内置演示口令，仅演示可用）",
  "bootstrap": { "user": "admin", "token": "你的口令" }
}
```

启动时即在空库里**播种**出这个管理员（口令**读一次、写进数据库**）。
只给 `token` 不给 `user` 时不播种，而是作为初始化凭据使用；两格都不给就打开 `/login` 手建。

**为什么不放环境变量**：环境变量会顺着 `docker inspect`、崩溃转储、子进程的环境快照漏出去；
而且它**不在数据库里**，备份一次数据库带不走它。这一轮之后，系统里需要"存"的东西一律入库，
**只有"打开数据库之前就要知道的钥匙"留在这个文件里**（密封口令、盐、装机凭据）——
这条口径是"配置一律入库、环境变量退场"的直接后果。

### 忘记口令 / 增删账号

**改口令、停用、删除都会立刻吊销该账号已登录的会话**（否则"我已经把他停用了"只是库里的一句话）。
唯一没有界面出路的局面是"唯一的管理员口令想不起来了"，所以有一条命令行：

```bash
npm run user -- list                       # 列出账号（不含任何口令材料）
npm run user -- passwd admin               # 重设口令（口令从标准输入读，也可用 L0_NEW_PASSWORD）
npm run user -- add dr-zhang clinician     # 新增账号
npm run user -- disable dr-zhang           # 停用（启用：enable）
```

它会拒掉三件事：删/停用/降级**最后一个能登录的管理员**、停用或删除自己、口令短于 8 位。

### 换密封口令（轮换）

上面那一节改的是**账号口令**（登录用）；这里改的是**密封口令** —— 解开库里密文的那把钥匙，
存在 `server-config.json` 的 `stateKey`。两者互不相干，但密封口令有一个额外后果：
**换了它，库里已经写进去的每一行都得重新密封一遍**，所以有专门的工具与顺序：

```bash
npm run state:rekey                                            # 试运行：报告有几行、这把旧口令对不对（不写任何东西）
npm run state:rekey -- --apply --new-key-file D:/keys/new.txt  # 真正重写
```

顺序（不要跳步）：

1. **停掉服务进程**。服务内存里是旧口令派生的密钥与派生缓存，它在轮换进行中写入的行会用旧口令 ——
   事务保护不了这种跨进程混合。
2. 跑试运行，确认"全部密封行都能用旧口令读通"。这一步失败通常意味着旧口令给错了；
   若只有个别行失败，那是那一行的数据坏了 —— 两者处置不同，工具会把行号与身份报出来。
3. 把新口令写成一行放到 `D:/keys/new.txt`（**不要**写在命令行参数里：那会进 shell 历史与 `ps`），
   再跑 `--apply`（加 `--yes` 可跳过"输入 `rekey`"这一步确认，交互确认是防手滑用的，不是安全边界）。
4. 把新口令写进 `server-config.json` 的 `stateKey`，删掉那个临时口令文件，然后启动服务，
   确认启动日志里的「口令来源」与「盐」两行符合预期。

三条要提前知道的：**不可逆**（没有"换回去"的路，执行前请确认新口令已按密钥管理流程归档）、
**不替你改配置文件**（工具只打印该写什么，免得"钥匙换了而人不知道"）、
**不刷新时间戳**（轮换没有改内容，`updated_at` 保持原样）。

### 三条边界（与上面那些一起读）

它仍然**不是安全边界**：没有 TLS、没有多因素、没有对接医院 CA/SSO、会话在内存（进程重启即失效）。
它挡得住"误入配置页随手改"与"无意的脚本调用"，挡不住有意冒充 —— 真正的边界是 T23。

两条纪律值得先说：**它不看病历正文**（要看内容只能走受控阅读：授权 + 留痕），
**也不提供"关闭门控"的开关**（阈值可配，但不能越过安全底线）。

## 它在验收上凭什么可信

三条互相独立的证据链，而不是"自测通过"一句话：

1. **同一批场景跑两套实现**：TS 实现与工具链里的 JS 参考实现（`tools/model-check`）逐项比对判定与错误码，有一条不一致就算失败。
2. **产物交给独立探针**：导出的 OFD 由 `tools/ofd-check` 解包、抽回数据、复算摘要并验签；导入侧做"导出 → 导入"闭环比对。
3. **契约用真实 HTTP 打真实服务**：`test:http` 把同一套契约直连服务端跑一遍，要求与内存参考实现通过数**逐一相等**。

密码学部分：SM3 / SM2 自研，并用国标示例向量与你运行时 OpenSSL 做**双向交叉验证**；
SM4 刻意不自研（离线环境找不到可靠的 S 盒核对来源，自研那次实测与 OpenSSL 逐字节全不一致）。

## 现在不能做什么（请先读这一节）

这一节比上面那些更重要 —— 开源之后一定会有人拿它去投标。

- **不能声称符合 GB/T 48666**：正文尚未公开，我们只承诺可扩展、可对齐。
- **不能声称支持 WS/T 500**：章节与数据元的编码还没跟标准原文核完（待核清单是明着列、没打勾的）。
- **不能作为合规证据使用**：自研密码学**未经第三方审计**，不满足合规要求；生产必须换成经认证的密码模块（内核留了替换点，注入后上层零改动）。
  **SM4 由运行时 OpenSSL 提供**，因此也不能宣称"国密三件套全自研"。
- **演示私钥可由公开种子推导**（`DEMO_SIGNING_SEED` 就写在源码里），只用于演示与可复现验收；生产私钥必须由设备保管、绝不落盘。
- **未配置医院签名服务时，签章整块不可用**：本系统**没有"内置软件签名"可回退**，未配置即拒绝签章（`E_SIGN_NOT_CONFIGURED`）。
  要用起来得在「配置管理 → 电子签名」填服务地址与字段映射 → 点「测试签名」→ 固定预置公钥与指纹。
- **受控阅读需要院内授权平台**（本系统只验签、登记与执行，**不签发授权**）；平台未接入时该功能整块不可用。
- **内涵类质控引擎未接入**（形式类规则是本地纯函数，已可用）；外部落位服务未接入。
- **没有鉴权、租户隔离、限流与审计防篡改**：`contract-server` 是**契约验证用的参考实现**，
  服务端**不可直接暴露到网络**（现场启用请用 `--auth-mode verified` + 凭证，见 `docs/`）。
- **并发写未做事务边界**（单线程内存实现不暴露竞态）；**大文档是整文档读写**，无增量同步；排版只做到启发式分页。
- **演示数据全部为虚构**：患者姓名一律掩码（`王**`），身份类号码是合成号；`artifacts/` 下跑出来的东西
  **不入库**（`.gitignore` 里整目录忽略），本机生成的那一份已由 `npm run scan:phi` 排查
  （不含明文患者信息与私钥，但**未检查项**如截图与加密产物仍需人看，报告里会列出来）。
- **本仓库是应用而非库**：`package.json` 保持 `private: true` 以防误 `npm publish`；分发靠 git，不靠 npm。

## 目录结构

```
src/
  model/     模型层、索引、机读信息、跨文书一致性、患者主索引
  core/      写会话（门控 / 留痕 / 签章 / 快照持久化）、建议与注解、审计报告
  crypto/    SM3、SM2、SM4 封装、签名与验签、认证加密信封
  ai/        模型接入层（离线模板与 HTTP 适配器、上下文包）
  sign/      医院签名服务配置与远程签名器
  import/    OFD / WS/T 500 导入、版式段落重建、ZIP 读取
  export/    OFD-H 与 WS/T 500 导出
  reading/   受控阅读（授权凭据、密钥交付）
  qc/        形式类质控规则包
  demo/      交互 Demo（服务端 + 界面 + UI 契约自测）
  server/    契约验证用的参考服务端
  security/  发布前隐私与密钥排查
tools/       独立探针与参考实现（ofd-check / model-check / editor-check）
schema/      文档模型 schema（`l0-document-model.schema.json` + TS 类型定义）
samples/     内置知识包与质控规则的样例资产（`packs/`、`qc/`）
docs/        能力矩阵与界面截图（`docs/images/`）
artifacts/   **不入库**：跑自测与 Demo 时自动生成（导出样例、探针报告、运行期状态）
```

根目录这两个文件**不能挪位置**，代码是按仓库根拼路径读它们的：
`hongyi-ai-qr.jpg`（`src/demo/demo-server.ts` 的 `/hongyi-ai-qr.jpg`）、
`phi-scan.reviewed.json`（`npm run scan:phi` 的复核记录）。
`.env` 是管理后台口令，**不入库**（见 `.gitignore`）。
