## 六、排版：四个出口与一个来源

**问题**：同一份文书，纸面由四处分别决定——编辑区 DOM 流（`flow-view.js:117`）、纸张视图 CSS 宽高（`ui.css:1587`）、打印 `@page`（`ui.js:104`）、导出 `paginatePages`（`ofd.ts:398`）。四处不同源，"屏幕/打印/导出一致"没有可测对象。

**做法**：排版结果作为数据统一产出。一个纯函数输出 `LayoutDoc`，四个出口只消费结果：

```
doc + layoutPlan ──► layout() ──► Page[] { lines: {nodeId, text, x, y, size, bold, blockKind} }
                                    ├─► 编辑区（流式，可编辑，局部重排）
                                    ├─► 分页预览（只读，逐页绝对定位）
                                    ├─► 打印（同一容器，浏览器不再重排）
                                    └─► 导出（OFD 逐页 XML）
```

当前四点缺口：

1. ~~排版结果没有出口~~ **已解决（2026-10-21）**：`GET /api/layout`（`demo-server.ts:4043`，按 `doc.export` 权限）下发 `LayoutDocument`，含每页每行的 `x/y/size/bold`、页眉页脚文本与坐标；界面只负责按 pt 摆位置。原缺口是 `RenderLine` 不带坐标、坐标只被 `buildOfdPackage` 消费（`ofd.ts:715-726`）。
2. 度量不统一。`estimateWidth` 按全角等于字号、半角等于半字号估算（`ofd.ts:124-138`），与浏览器字体度量有差。预览或打印一旦改绝对定位，差值会表现为"预览换行位置和打印不一样"。因此 P1 的第一个动作是定度量来源：前端沿用同一套估算（屏幕字宽略怪，但四处一致），或引入字体度量表（`宋体`、`仿宋_GB2312` 字宽表）。二者先定，否则后续返工。
3. 孤行寡行只处理一种情况。`paginatePages` 只保证标题不落页底（`ofd.ts:437-441`），正文无 widow/orphan；`keepWithNext` 在类型与 schema 里声明，全仓无消费方（`model/types.ts:109`）。
4. 一致性没有用例。B81 的十三条断言都是对源文件跑正则（`ui-self-test.ts:2969-2998`），无几何或页数断言；`tools/` 下无版式探针。

**验收口径**：新增探针 `tools/layout-check`，对同一份文档输出四份行坐标，按 `nodeId` 逐行对齐比对：页数相等；每行 `x/y` 容差 ≤0.5pt 且 `text` 完全相等；任一行缺失或顺序不同即失败。这条探针存在后，一致性才有可失败的用例，也是 P3/P4 的准入条件。

**探针已建**：`tools/layout-check/layout-check.mjs`（`npm run verify:layout`）。它不 import 仓库源码，自己读 ZIP、解 Content.xml，再与 `GET /api/layout` 的快照对拍，五条检查 C1–C5 全过才算通过；T27-L10 用"挪 3pt / 改一字"证明它会红。覆盖边界：只对拍「预览 vs 归档件」，编辑区与打印消费同一份坐标，靠结构断言而不参与坐标对拍。

## 十三、不得宣称

1. 不符合 GB/T 48666：正文未公开，命名空间用 `extensions` 占位，`tools/ofd-check` 只做结构检查。
2. 不符合 WS/T 500：只有最小映射与双向闭环验收，OID 与数据元待院方核对。
3. "国密三件套全自研"不成立：SM2、SM3 自研，SM4 由运行时 OpenSSL 提供，均未经第三方审计。
4. 不得作为合规证据：生产必须换经认证的密码模块（内核留替换点）。
5. 演示私钥可由公开种子推导（`DEMO_SIGNING_SEED`），只用于演示与可复现验收。
6. 未配置医院签名服务时签章整块不可用，无内置软件签名可回退。
7. 受控阅读分两句说：生产侧不签发授权（只验签、登记、执行）；仓库内存在演示签发者（`controlled-reading.ts:144-174`），演示能签不等于产品具备签发能力。
8. 内涵类质控是"未配置即不可用"（引擎已接入，默认 `none`）；外部落位服务未配置即拒。
9. 无租户隔离，无 TLS/MFA/CA/SSO；`contract-server` 默认 `trusted` 模式，不可直接暴露到网络。
10. 排版可说"预览与归档件逐页、逐行、逐字、坐标一致（容差 0.5pt），由独立进程解析 OFD 对拍验证（② 档）"；打印可说"每次打印都留痕，记谁、何时、第几版、几页、是否正式件，留痕失败不出纸"。不得说"编辑区/打印也逐行对拍过"（靠同一份坐标，未单独比对）、"与 OFD 阅读器逐像素一致"（宽度按估算）；不得说支持套打、静默打印、打印件可作归档原件（留痕未进审计报告附件，正式件页脚声明未做）。
11. 无时间戳，无第三方存证：两侧都是局部链式结构，删一条当场可发现，但持有库文件者能整链重算；不得称"不可抵赖""已存证""证据保全"。
12. 不得对外报采纳率、修改率数字：有口径，无评测集。
13. 书写时长只在 `trusted:true` 时可报数，它是质控线索，不是绩效口径。
14. 演示数据全部虚构（姓名掩码、身份类号码合成），`artifacts/` 不入库。

| 序 | 主线 | 规模 | 最小可用口径 | 验收 |
|---|---|---|---|---|
| 1 | 审签界面五个按钮（K22） | 小 | 提交审核、通过、退回、作废、归档 | 服务端四接口与 B76 已通，验收只看界面是否真调到 |
| 2 | 排版引擎与只读预览（P1a + P2 + P6） | 大 | **P1a/P2/P6 已完成（2026-10-21）**：`GET /api/layout` 下发页与行坐标，界面逐页绝对定位；`tools/layout-check` 独立对拍预览与归档件（C1–C5，容差 0.5pt） | 剩余：字体度量接入（现按全角/半角估算）、编辑区与打印的坐标对拍 |
| 3 | 打印收口（P4） | 中 | 页眉页脚与页码、草稿水印、打印留痕**已通**（先落痕再出纸）；剩余留痕进审计报告、正式件页脚声明、静默打印参数 | 纸面水印随状态变化；审计能查到谁在何时打了第几次 |
| 4 | 评测集与标注（D3 + G5） | 中 | 首版 100~200 份，固定口径，可一键回放 | 能给出"上一版到这一版修改率变化" |
| 5 | 真实 ASR + 术语包（I1 + A3） | 中 | 一家可用院内 ASR + 一张能加载的术语表 | ③ 档：真实端点实测；术语包载入即生效（不再是 `term: []`） |
| 6 | 编辑态流式排版（P3） | 大 | 行盒渲染 + 按行区间局部重排；光标不丢、滚动不跳 | 移至 V1.1 验收：P11 p95 ≤50ms（真浏览器 + 目标终端）；千页插入线性度 |

排序理由：

- K22 排第一，因为它是全表投入产出比最高的一条：接口、内核、用例都在，只差界面，而它正是端到端演示断掉的地方。
- 排版排第二，因为打印是归档入口，打印真实性由排版决定；先做打印预览而不做排版，等于把浏览器排版固化成产品版式，以后改不动。
- 评测集排第四，没有它，第 2、3、5 项以外的 AI 改进都无法验收，"效果变好"只能靠主观判断。
- P3 移出 V1：它依赖 P1a 的行盒与度量，M/5 难度放在 V1 会让范围不可控。

**明确延后（决策，不是遗漏）**：套打、静默打印参数、院内 RAG（I8）、多模态与 DICOM（I9）、患者版解释（I10）、ICD/DRG 预编码（I4）、EMPI 接库（K14）、租户隔离与信创互认（G4/K9）、TSA（G9）。

I4 单列一句：若目标客户按病案首页质量考核付费，它的商业权重高于排版，需要在立项时单独决策，不适用本表的通用排序。

## 十五、对标用法

1. 审签几态几动作。
2. 有没有能关掉门控的开关。
3. 界面能不能点一句跳回来源。
4. 导出件有没有独立探针验证。
5. 屏幕上的换行位置和导出件里是否一致，拿什么证明。答"我们的排版引擎统一"却拿不出逐行对拍结果的，就是没测。
6. 打印件上有页码和文书号吗，草稿与已签打出来有区别吗，打印记不记留痕。三条缺一条，归档时会被退。
7. 字体度量从哪来。答不出或答"浏览器自己排"的，屏幕与纸面必然是两套。
