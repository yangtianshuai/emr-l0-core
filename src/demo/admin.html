    鉴权模式 会话寿命(分钟) 登录限流(同身份) 登录限流(同来源) AI 限流(每分钟) 导出限流(每分钟) 锚定节奏(每 N 条) 锚点种子
    这几项落在服务进程的内存结构上（会话表 / 限流器 / 锚点签名者），所以保存后要 重启服务才生效 —— 其余配置（模型 / 采集 / 落位 / 质控）改完立即生效。 原先它们在环境变量里，因此"改名、改值、忘重启"三种错法长得一模一样。
    生效配置指纹用于比对配置是否一致
    对白名单内的配置字段取值后取哈希（SHA-256 前 16 位）。密钥值不在白名单内， 因此更换密钥不改变指纹，是否配置密钥会改变指纹。比对时把这几行提供给对方即可。
    工作区破坏性动作
    清空的是病历本身：全部患者与文书（含留痕）、已落盘的旁挂数据（AI 建议 / 标注）、 阅读授权登记；清完按出厂演示数据重新播种。 不在清理范围内：账号、能力配置、系统策略、知识资产（模板 / 规则 / 控件）、管理审计 —— 重置之后最该查得到的，恰恰是"谁在什么时候清空了这台机器"。
    这是唯一一个两种模式都要求管理员身份的破坏性动作（医生端不设入口：那里没有登录入口， 摆了就是个永远点不动的按钮）。医生端已打开的页面建议刷新 —— 它手里的版本号还是重置之前的。
